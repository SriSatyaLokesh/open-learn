# OpenLearn Landing Page Plan

## 1. Goal

Create a landing page that makes OpenLearn immediately understandable to a new visitor and clearly communicates why it is useful for people who learn from YouTube and the open web.

The page should optimize for:

- Human understanding and conversion
- SEO
- Answer Engine Optimization (AEO)
- Generative/AI search discoverability (GEO)
- Clear product positioning
- Fast path to `Start Learning`

Primary principle:

> Explain the product before explaining the features.

---

## 2. Core Product Positioning

### Recommended positioning

> **Turn the content you find online into learning you can actually finish.**

Supporting explanation:

> OpenLearn turns scattered learning content from YouTube and the open web into structured learning paths, so you can focus, practice, track your progress, and complete what you started.

### Product category

OpenLearn should be presented as:

> **An open learning platform for turning online content into structured, actionable learning.**

Avoid positioning it primarily as:

- An LMS
- A YouTube alternative
- A course marketplace
- A certificate platform
- A gamification platform
- An AI learning platform

Those may describe parts of the product, but they should not define it.

---

## 3. Primary Audience

Primary audience:

> **People who learn from YouTube and other online resources.**

Typical user:

- Finds a topic they want to learn
- Searches YouTube/the web
- Finds multiple videos/resources
- Starts learning
- Gets distracted
- Loses track of progress
- Starts another course/resource
- Eventually abandons the learning goal

Secondary audiences can be addressed later:

- Self-taught developers
- Students
- Career switchers
- Technical professionals
- Community curriculum creators

Do not make the hero claim that OpenLearn is for "everyone."

# 28. Implementation Acceptance Criteria

The landing page is successful when a first-time visitor can answer these questions within approximately 10ΓÇô20 seconds:

- What is OpenLearn?
- Who is it for?
- What problem does it solve?
- Why isn't a normal YouTube playlist enough?
- What happens when I use it?
- How do I start?

### SEO acceptance criteria

- Unique title
- Useful meta description
- One clear H1
- Logical H2 hierarchy
- Search-intent-aligned copy
- Crawlable text
- Internal links
- Canonical URL
- Open Graph metadata
- Structured data where appropriate
- Fast page performance
- Mobile-friendly layout
- Accessible semantic HTML

### AEO/GEO acceptance criteria

- Direct product definition
- Explicit audience definition
- Explicit workflow
- Question-based FAQ
- Short direct answers
- Consistent product terminology
- No contradictory claims

### UX acceptance criteria

- Primary CTA visible above the fold
- Product UI visible above or near the fold
- Clear visual hierarchy
- No unnecessary animation
- No confusing CTA competition
- Mobile layout works properly
- Accessibility considered from implementation

# 29. Recommended Build Order

Do not start by writing all the copy.

Build in this order:

1. Finalize one-sentence positioning
2. Finalize hero
3. Finalize primary CTA
4. Finalize problem/solution narrative
5. Design information architecture
6. Map existing product functionality to each section
7. Remove claims unsupported by the current product
8. Write landing-page copy
9. Add SEO metadata
10. Add AEO/GEO structure
11. Add structured data
12. Implement responsive UI
13. Test performance/accessibility
14. Test the page with a person unfamiliar with OpenLearn
15. Revise based on whether they can explain OpenLearn correctly
